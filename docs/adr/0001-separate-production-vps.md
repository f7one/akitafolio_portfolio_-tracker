# ADR-0001: отдельный production VPS для Telegram-бота

- **Статус:** accepted
- **Дата:** 2026-08-17
- **Обновление:** 2026-08-23
- **Владелец решения:** project owner

## Контекст

На VPS `194.87.83.103` одновременно работают сайт в Docker Compose и Akitafolio
как root systemd service. Бот публично принимает пользовательский ввод, обращается
к нескольким внешним API и использует зависимости с известными security findings.
Telegram token ранее попал в Git history и `journald`; Telegram token и Infura ID
отозваны, поэтому текущий бот остановлен функционально и допустим downtime.

Пользовательские адреса, xpub, custom tokens, настройки и portfolio history нужно
сохранить. Сайт, его CI/CD, Docker, Caddy и узкие права пользователя `deployer`
не должны изменяться в рамках миграции бота.

## Решение

1. Первым этапом master plan перенести Akitafolio на отдельный VPS
   `72.56.120.66` в Timeweb Cloud. Предыдущий кандидат `138.124.85.193` исключён как
   неисправный. До развёртывания инвентаризировать и, после отдельного
   подтверждения владельца, удалить с target прежний Outline VPN.
2. Использовать отдельную VM как границу отказа и компрометации; не объединять
   бота с сайтом, его Compose project, volumes, networks или `.env`.
3. По решению владельца сохранить root SSH как по отдельному ключу, так и по
   паролю: `PermitRootLogin yes`, `PasswordAuthentication yes` и
   `KbdInteractiveAuthentication no`. Пустые пароли запрещаются. Это принятое
   security-исключение компенсируется уникальным сгенерированным паролем,
   firewall-ограничениями, fail2ban, уменьшенным числом попыток входа и
   мониторингом SSH-журнала. Provider console остаётся аварийным каналом.
4. Запускать бот напрямую через systemd от непривилегированного пользователя
   `akitafolio`. Операторский SSH-пользователь использует отдельный ключ, не
   состоит в `docker` и не получает общий sudo; допустимы только точечные команды
   управления конкретным systemd unit.
   Environment-файл хранится вне каталога кода как `root:root` с mode `0600` и
   подключается через `EnvironmentFile=`; JSON-данные принадлежат `akitafolio`
   и имеют mode `0600`.
5. Бот не публикует входящие порты. Firewall разрешает только административный
   SSH из согласованных источников; приложению нужны исходящие DNS/HTTPS/RPC.
6. Старый `.env` не переносится. Новые Telegram token и Infura Project ID
   создаются после устранения утечки URL в логах и хранятся вне Git.
7. При остановленном старом сервисе напрямую по проверенному SSH переносятся
   `saved_addresses.json` и `portfolio_history.json`. Целостность подтверждается
   SHA-256; содержимое не попадает в команды, чат или логи.
8. Старый сервис остаётся остановленным как rollback target до явного
   подтверждения владельца. Затем с общего VPS удаляются только файлы и секреты
   бота.

## Статус исполнения

На 2026-08-23 target подготовлен и сервис работает на отдельном VPS; старый
`tg-balance-bot.service` остановлен и отключён. JSON-данные перенесены с
совпадающими SHA-256 после остановки старого service. Владелец подтвердил
ручной Telegram smoke-test и смену раскрытого root-пароля. Удаление старой
установки сознательно отложено до отдельного rollback-window approval.

## Рассмотренные альтернативы

### Оставить бот на VPS сайта под отдельным Linux-пользователем

Дешевле и проще, но сохраняет общий kernel, ресурсы, административную плоскость и
последствия компрометации. Отклонено из-за публичной поверхности бота и ценности
работающего сайта.

### Запустить бот отдельным Docker Compose project на VPS сайта

Улучшает воспроизводимость, но не создаёт требуемую VM-границу, усложняет права
Docker и может затронуть существующий production Compose. Отклонено.

### Оставить root SSH только по ключу

Это рекомендуемый вариант с меньшей поверхностью brute-force атак. Отклонён
владельцем в пользу дополнительного аварийного способа входа по root-паролю.
Риск принят явно и требует перечисленных в решении компенсирующих мер.

## Последствия

- Уменьшается blast radius между ботом и сайтом.
- Появляется отдельная стоимость VPS и обязанность обновлять, мониторить и
  резервировать ещё одну систему.
- Deployment и recovery бота становятся независимыми от сайта.
- Перенос данных требует короткой остановки записи и проверки целостности.
- До исправления dependency, rate-limit и storage findings VM-изоляция снижает
  инфраструктурный риск, но не устраняет уязвимости приложения.

## Rollback

Если smoke/integration tests на новом VPS не проходят, новый сервис
останавливается. Старый сервис можно вернуть только с новыми секретами и после
закрытия утечки секретов в логах. Одновременный Telegram polling запрещён.
Старую установку не удалять до подтверждения владельца.

## Security invariants

- Никаких приватных ключей криптокошельков: только публичные адреса/xpub.
- Секреты не передаются через Git, deployment archive, shell arguments или чат.
- Root SSH допускает ключ и пароль как документированное исключение; пустые и
  keyboard-interactive пароли запрещены, brute-force controls обязательны.
  Сервис остаётся non-root; оператор — без общего sudo/docker.
- JSON-данные и `.env` доступны только необходимому service account/root.
- Каждый этап cutover сохраняет проверяемый путь отката.
